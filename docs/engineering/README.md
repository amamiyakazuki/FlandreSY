## 已确认的交付方式

每个获批模块使用模块分支，经提交、推送 GitHub、PR 和 CI 检查交付。合并和正式版本发布单独处理。一个模块完成后更新状态，再决定下一模块。

## 记录要求

- 计划写目标、边界、未决事项与验收标准；不以任务勾选代替证据。
- 验收写确切提交、命令/场景、结果与未验证项。
- “代码检查”“自动测试”“构建”“真机”“服务端确认”分开记录。
- 不把旧提交的测试结果当成本模块的新证据。
