# C2：本地设备列表一致性、导入校验与刷新反馈

状态：用户已确认全部 A 方案，已完成实现与本地验收，进入 main 推送 / CI 收口。见 [C2 验收](c2-device-consistency-acceptance.md)。原规划基线：main `606a11c6922eca1e4efdf07b1769c359525c57d2`（C3a 已完成，288 项测试通过 / 1 项可选截图跳过，两平台 CI 通过）。这些是既有基线，不是 C2 验收结果。

## 目标与问题

本模块保护“设备”页的本地快捷入口列表，不重做服务端设备管理。

| 问题 | 当前事实 | 目标 |
|---|---|---|
| RA-02 刷新覆盖编辑 | 刷新保存开始时的整份列表；期间的新增、改名、删除、导入可能被晚到结果覆盖。提示与 busy 共用状态 | 网络只更新仍对应原设备的查询字段；最新用户编辑保留；真正的在途状态不被提示清除 |
| RA-03 导入缺少业务校验 | `[{}]`、重复 ID、缺设备码可通过；导入仅据排序恢复序号；保存未完成就可能返回成功 | 整批验证、明确替换范围、避免撞号；成功必须以保存完成为依据 |
| RA-14 刷新伪成功 | 普通查询失败被吞掉，仍写新刷新时间和“已刷新” | 区分全成功、部分成功、全失败、无需查询；旧结果有标识 |

本次复核的相关补充：shell 只接收导入 bool，无法区分格式错误和保存失败；`hotwater_actions` 也会直接写同一个 `local_devices_json` 仓库，可能绕过设备保存队列。二者属于本计划的必要接线范围，已完成修改。

## 已确认决定（全部 A；保留原备选供追溯）

| 决策 | 推荐 A | 备选 B |
|---|---|---|
| 刷新期间编辑 | 允许新增、改名、删除；返回时只合并仍有效设备的状态 | 刷新期间锁住编辑；实现较简单，但慢请求会挡住操作 |
| 导入语义 | 保留现有“整表替换”，校验后展示替换数量并二次确认；坏一项则整批拒绝 | 改为合并导入；需另定同 ID、同设备不同名称等冲突规则 |
| 保存失败 | 新增/改名/删除/导入均保存成功后才显示完成；失败保留原列表及输入供重试 | 先显示编辑结果再标记未保存；需要更多脏数据与恢复管理 |
| 刷新失败的旧状态 | 保留上次结果，但明确标记“上次结果 / 本次查询失败”，不当作当前可用 | 将失败项显示为“未知”；信息更少但界面简单 |
| 新导入类型 | 仅允许本页已支持的 washer / drinkingWater；其他类型整批拒绝并解释 | 接受隐藏类型作为只读备份；需额外展示与恢复说明 |

用户已确认全部 A，并明确：空数组不用于导入清空；导入仅完成本地保存，不自动发起状态查询，由用户再点刷新。这样“导入成功但网络不可用”不会被混成失败或伪成功。

## 具体范围

### 1. 列表一致性与保存

- 为列表变更建立统一串行提交入口。新增/改名/删除/导入及刷新结果保存都在执行时基于最新列表计算，成功保存后发布状态；不能把排队前捕获的旧整表晚写回去。
- 网络请求不占住本地编辑队列。刷新开始记下目标 ID、类型、设备码及必要版本；返回只改状态字段，保留名称、排序、其他设备及之后新增内容。
- 删除的设备不能复活；删除后重建或导入复用同一个 ID 时，旧响应也不得套到新记录。导入替换让此前刷新批次失效。
- 刷新任务独立去重：连续点击共享同一次刷新或忽略重复请求；编辑成功提示、提示定时消失、保存错误都不能释放网络在途标记。异常、切号、销毁后必须正确收尾。
- 保存失败保留原列表；改名弹窗保留输入，导入保留待导入内容可重试，不重复要求用户复制。异步保存结果不得覆盖后续操作反馈；SharedPreferences 返回 false 不能因其内存缓存已变化而判成功。
- 统一热水操作对本地设备状态字段的保存入口，避免绕过队列；只调整列表提交协调，不改变热水协议、会话、启停与 40 分钟规则。设备状态保存失败与设备关水结果分开说明。
- 恢复和新增 ID 使用同一防撞规则：参考现有 ID 尾号和排序值，并检查当前 ID 集合；导入后的下一次新增、重启后的新增均不能撞号。

### 2. 导入校验与旧数据兼容

导入分“解析验证 → 展示摘要并确认 → 保存 → 生效”；校验失败、用户取消、保存失败均不替换当前列表。

| 数据 | 推荐验证规则 |
|---|---|
| 顶层 | 非空 JSON 数组，条目必须为对象；空文本、空数组或其他顶层类型拒绝 |
| id | 非空字符串；去除首尾空白后整批唯一，不把数字/对象强转成 ID |
| deviceType | 新导入仅 washer / drinkingWater，明确拒绝 unknown、shower798 及未知枚举 |
| 设备码 | washer 有当前支持形态的 qrUrl 且设备标识非空；drinkingWater 有非空 cd。不能只凭字符串含 `uuid=` 就接受空标识 |
| 同设备重复 | 对已规范化的 qrUrl / cd 检查重复；同一设备换 ID 也拒绝整批，不擅自选择某条。只做明确可验证的规范化，不猜测不同 URL 一定是同一实体 |
| 名称与展示字段 | customName 为字符串，允许空名并沿用既有展示兜底；可选文本字段只接受字符串或 null，类型错误拒绝 |
| 排序 | 缺失用既有默认；接受非负整数或兼容旧导出的整数字符串，非法/负数拒绝；相同排序值保留输入顺序，不把排序当唯一身份 |
| lastStatus / 时间等缓存 | 可读取旧文件，但不作为本次查询证据，不纳入当前可用台数；导入后显示未查询或历史结果，不相信外部提供的“刚刷新”时间 |
| 未知附加字段 | 忽略，不写入运行时行为；必要字段仍严格验证 |

- 确认弹窗说明“用 N 条替换当前 M 条”，M 计入旧隐藏类型；取消保留全部。确认前后列表发生编辑则提示重新确认，不能悄悄覆盖新编辑。
- 严格导入验证与已有本地存储读取分开，避免升级时把旧 unknown / shower798 / 缺少新元数据的记录自动删掉或使整库无法读取。
- 普通编辑/刷新保留未涉及的旧记录；若旧数据有空 ID、重复 ID 等无法安全定位的情况，保留原数据并提示，禁止针对歧义条目写回，不自动重编号或清空。完整历史数据修复工具不属于本模块。
- 保留现有导出 JSON 的可读性；本页支持的合法设备应能导出后重新导入。包含不支持类型的旧备份可继续导出，但严格导入会明确拒绝，而不是静默丢弃部分条目。

### 3. 刷新反馈与状态可信度

仅查询现有支持的洗衣设备；饮水快捷入口不伪造实时状态，不新增饮水或 798 查询接口。

| 结果 | 页面行为 |
|---|---|
| 有查询目标且全部成功、保存成功 | 显示成功数量和本次成功时间 |
| 部分成功 | 成功项更新；失败项保留上次结果并标记查询失败；显示成功/失败/跳过数量，不称“全部已刷新” |
| 全部失败 | 显示失败，不推进成功时间，不把上次“可下单”表现为刚查询得到 |
| 无可查询项 / 只有饮水设备 | 显示“没有可刷新状态的设备”及跳过说明，不报告成功 |
| 鉴权失效 / C1 重登门禁 | 沿用现有登录引导；保留列表与旧值，结束刷新；不能由旧账号响应覆盖新账号 |
| 查询成功但保存失败 | 显示保存失败，不称整体完成，不覆盖用户配置；提供重试，保留最后已保存状态 |
| 期间列表改变 | 只采纳仍有效条目的结果；丢弃结果不计成功，摘要与最终列表一致 |

刷新状态、编辑/导入提示、保存状态各自维护。每台设备有最近查询结果及是否可信的信息；如需要落盘时间，新增字段须可选并兼容旧文件。没有时间证据的历史状态不能凭升级时间补成“刚查询”。

列表的状态标签和首页“可用洗衣机”计数采用相同规则：本次失败、导入及重启未核对的缓存不作为当前可用；可显示历史值。不新增定时轮询或承诺状态一直实时，成功结果也标明查询时点。

## 不在范围内

- 洗衣订单轮询/按钮状态、真实下单/支付/启停、账号历史归属、权限、iOS BLE、更新包或发布。
- 云同步、跨设备合并、拖拽排序、批量编辑、导入逐项修复器及设备列表视觉重做。
- 不修改 C1 保全快照或解除旧订单门禁，不放宽 C3a 接口校验。
