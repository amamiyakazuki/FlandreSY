## 实施边界

### 日志一致性

- 恢复、追加、清空共用明确顺序和清空代次；清空之前的恢复/快照不得覆盖之后的状态。重复清空合并或排队，不能留下未处理异常。
- 清空前旧记录被移除，清空后产生的新记录保留。持久化失败不能报告成功；失败后允许重试，后续日志仍可继续保存。
- 仓库检查 false/异常，必要时重新加载缓存；内存内容、复制内容、当前页面和重建日志器结果需要一致。保存失败只显示诊断存储状态，不递归写日志造成循环。
- 保持既有 16000 字符上限，不引入云端日志、自动上传或后台收集服务。

### 超时与资源释放

- 一次请求从发起连接起共用所选期限，响应头和正文不重新计时；期限可注入以便本地测试。
- 超时后清理该请求，迟到连接到达也立即终止；不得关闭共享客户端误伤其他请求。迟到返回不更新账号、cookie 或业务状态。
- 超时仅表示本次结果未确认，不代表服务端没有执行。控制操作不得自动重发；保留现有会话核对、旧数据门禁与明确鉴权拒绝规则。
- 本期不改变 BLE 扫描/握手/连接超时，不对整个开水流程设置新的统一上限，不扩展自动重试、熔断或请求平台重构。

### 诊断脱敏

- 保留服务类别、操作阶段、结果/受限错误码和异常类型；当前未采集耗时，不新增遥测；手机号、账号、设备/订单标识使用占位或不可还原的本次运行关联标识。token、Cookie、Authorization、签名、短信验证码、支付串和蓝牙凭据不进入日志。
- 日志调用源头不拼入原始敏感字段；统一日志入口兜底过滤，再覆盖历史读取与复制路径，不能只在复制时遮盖而仍将原文落盘。
- 不把原始 URL 查询参数、HTTP 正文或异常堆栈直接拼入用户诊断；保留可理解的错误类别与错误码，不把一切错误改成“未知”。检查现有三服务异常生成点，修改仅限诊断内容，不改变接口成功/鉴权判定与发送参数。
- 旧诊断按选定策略迁移；迁移写入失败不能直接展示/复制旧原文，提示失败并重试。原始旧诊断不复制到普通备份键。不得处理或清除业务数据来实现日志脱敏。
- 测试使用合成敏感标记，不读取真实账号、密码或历史私人日志；无任何自动上传。
