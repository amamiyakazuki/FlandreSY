# C1：移除产品模拟模式与旧数据保全

日期：2026-10-16。状态：用户已批准整个 C1；实现和本地检查完成，已创建 [PR #4](https://github.com/amamiyakazuki/FlandreSY/pull/4)，远端检查见验收记录。关联问题：RA-01、DEBT-02（根目录 bug.md）。

## 已确认

- 应用移除面向用户和开发运行的模拟模式，只保留真实业务组装。
- 模块分支加 PR；本目录跟踪精简计划与验收记录。
- 本模块按已批准计划实现；不同时修复设备竞争、洗衣状态、iOS 蓝牙或升级分包等其他模块。

## 为什么不能只删开关

旧版真实和模拟模式共用普通存储。开关 false/缺失不证明从未模拟；洗衣/饮水订单通常没有可信来源标记，真实风格的订单号也可能由模拟实现产生。旧账号资料可能与安全仓库的真实 token 不匹配。热水旧会话有 simulated 字段，删字段必须保留读取兼容。

因此应在自动恢复、旧订单归属、轮询之前完成本地数据保全和所选恢复限制。

## 已选数据策略：A 保守保全

用户于 2026-10-16 确认：旧数据保留，各服务首次使用重新登录；来源不明活动记录核对前不自动删除、不用于控制设备。证据不足时保留待核对状态，暂时限制对应业务。

不按订单号外观、金额、设备名猜测并删除记录。新安装没有旧数据迁移提示。

## 实施范围

1. 删除设置开关、SIMULATE_BACKEND 生效路径和生产缺省 Fake/假支付依赖；旧偏好仅供迁移读取，不能再控制模式。
2. 生产依赖显式注入；FakeShuiRuntime 改为反映实际用途的名称。离线测试替身移入 test/support，测试显式注入。
3. 增加版本化、可续跑的本地保全流程：原始普通存储备份、逐服务/记录恢复状态、失败保护；安全凭据留在安全仓库。
4. 旧明确模拟记录保留为不可执行记录；来源不明活动单保留原 ID/归属/凭据，在核对前防止新建重复订单。
5. 真实重新登录只解除身份限制，不自动认定旧订单有效；只读查单还须验证有效业务响应及可确认的归属。失败、空响应或查不到都不能当作结束。
6. 热水不重发启动来验证，不把模拟会话改成真实；保留原 session ID 和停止所需凭据。未核对期间暂缓改写旧记录，确认后恢复原有正常规则。
7. 提供可见的待核对/保全失败原因与重试、重登入口；不新增一键删除活动记录继续下单。
8. 更新关联说明、回归测试和验收记录。无法还原已被覆盖的旧历史，不承诺恢复所有丢失数据。

A 会暂缓迁移期间的自动旧订单归属及本地会话清理，直到证据满足；这是本模块已批准的迁移例外。确认后的正常业务继续遵守既有单活动单、归属不可跨账号接管、热水幂等和 40 分钟本地恢复规则。
