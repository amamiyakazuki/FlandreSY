# 项目优先级总览

更新：2026-10-16。原审查整理基线：main `86697a9`；新增 C3a 修复提交 `26edd0b2a7245347dad7ce3d3d5d6bc31fc4c879`。C3a 已获单独批准并完成本地验证，其他模块仍待用户决定。

## 怎么看 P0 / P1 / P2

优先级表示处理紧迫程度；“代码确认 / 待真机验证”表示证据程度，两者分开看。模块编号 C2、C3 等是范围标签，不是优先级。

| 级别 | 本项目采用的口径 | 处理原则 |
|---|---|---|
| P0 紧急 | 已确认的严重事故，例如持续错误扣费、不可恢复的数据破坏、失控设备操作或广泛无法使用 | 暂停正常开发，先控制影响和恢复 |
| P1 高优先 | 核心操作或记录可信度存在高影响风险；也包括特定受支持平台核心功能不可用 | 下一批优先处理；明确触发条件与证据，不能把风险说成已发生事故 |
| P2 常规修复 | 局部功能错误、数据一致性、状态展示或恢复体验问题，尚无证据达到上述影响范围 | 按模块成组修复；同级内结合实际使用频率与依赖排序 |
| P3 后续完善 | 次要入口、文案、死代码或一般体验收尾 | 排在关键正确性之后 |
