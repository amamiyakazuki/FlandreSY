## 已实现行为

- 首次引导仅说明，不申请权限；扫码入口按需申请相机。更多页进入时只读检查，用户可显式申请或打开设置，返回前台重查。打开设置失败不会宣称成功。
- 共用权限服务，Android ≤30 检查/申请前台定位并另查定位服务，31+ 只申请 scan/connect。SDK 版本通过原生平台接口读取，未知版本不猜。已授予不重弹，同权限合并、不同权限串行。
- 拒绝、永久拒绝、受限制、未知、缺失结果、平台异常和不支持分别反馈。空集合不算成功，申请异常可重试；蓝牙开关与硬件支持仍由传输层检查。
- iOS 住理开关水明确暂不可用，在运行时、适配器及真实传输入口拦截，先于控制相关 HTTP 或 BLE 调用；不申请无用途蓝牙/定位权限，不误报为权限拒绝。权限页和热水详情可见原因。
- 已有 iOS 住理会话（含过期、准备中、不确定记录）及 C1 待核对保护继续保留，不自动清除，不把阻止控制当关水成功。原有显式本地清理流程保留；登录、历史查询、798/U净网络功能继续沿用既有规则。
- 移除通知请求、通知用途说明和 Android 通知权限声明；CocoaPods 仅开启相机权限宏，明确关闭蓝牙/定位/通知宏，并保留其他编译定义。未主动撤销系统已有授权，未添加消息发送。
- Android 目标选择规则未变；未添加同名/RSSI 猜测、UUID 转 MAC 或未经证明的设备身份协议。依赖和最低平台版本未升级。
