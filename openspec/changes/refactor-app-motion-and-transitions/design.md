## Context

Flutter 应用以 ShuiShell 的单个 ShuiRoute 和 AnimatedSwitcher 组织大部分页面，扫码另用 MaterialPageRoute。详情、主导航都淡入淡出；Shell 与各页面分别持有弹层；底栏空间由各页硬编码。ShuiPressable 只有透明度反馈；列表缺少稳定条目级过渡；接水完成由 Shell 检查消息后自动回首页。

现有账号和热水规范仍有效。工作区已有大量用户修改，实施必须以当前内容为基础，不回退它们。本次仅生成文档；遵循用户明确指示不更新 P_PLAN。完整范围在同一 change 中管理，实施时仍按模块交付审查。

## Goals / Non-Goals

**Goals:**
- B 风格：轻压、柔和减速、小控件克制回弹，大页面稳定落下。
- 有效输入即时可见；导航、弹层、内容变化拥有不同且一致的语义。
- 动画、布局、返回、焦点和异步结果共同形成连续体验。
- 减少动效、快速输入、窄屏与大字体下依然可操作。

**Non-Goals:**
- 不重画应用主题、不新增业务服务、账号体系或支付协议。
- 不修改热水终态判定和轮询间隔，不以动画计时作为业务成功依据。
- 不要求每次后台刷新、每秒倒计时或不可点击装饰播放动画。
- 不新增角色素材；本轮灵动感主要来自交互元素，不依赖全局装饰循环。

## Decisions

### 1. 统一动效令牌及输入状态

在 ShuiMotion 集中管理语义时长、曲线、位移和减少动效策略。初始调校值：触摸反馈 100ms、局部变化 180–220ms、路由 260ms、弹层 220ms；小按钮压到约 0.97，大卡片约 0.99。选中图标允许一次轻微回弹，页面和文字不越界弹跳。这些值是体验调校起点，不是等待业务执行的时限。

ShuiPressable 处理按下、松手、拖动取消、失焦、禁用及键盘激活；业务回调立即执行且一次激活只执行一次，不等待回弹。优先复用 Flutter 标准焦点及语义能力；开关、输入框保留其原生交互，避免叠加双重反馈。相比给每个页面独立添加动画，这样能统一覆盖并控制维护成本。

### 2. 路由结构与生命周期

保留 ShuiRoute 作为目的地模型，使用 Flutter Navigator/Page 栈表达详情层级，主 Tab 保留各自的浏览状态。路由元数据描述父页面、转场类型、底栏策略；页内返回、系统返回和受支持的返回手势消费同一导航状态。优先内置 Navigator，不引入路由依赖，也不继续用单个 route 字段模拟多级历史。

主 Tab 内容使用短距离顺向移动加淡入，底栏标记平滑迁移；详情从右进入，旧页面轻微退让，返回逆向。快速导航以最新目标为准，重复点同一目的地只反馈触摸，不追加重复页；退出页不可点击或获得辅助功能焦点。应用布局方向反转时导航方向随之调整。

保留滚动位置、订单分类和有效未提交选择。页面保活不等于后台活跃：离屏页暂停 UI 时钟及页面专属轮询，runtime 负责的有效会话查询遵循既有生命周期；恢复时避免创建重复计时器。账号详情返回账号中心；任务页普通返回回到入口，完成页的显式“返回首页”到首页。离开洗衣、接水流程仍执行既有必要清理，浏览状态不能保留失效订单。

### 3. 底栏和安全区统一拥有者

| 场景 | 策略 |
|---|---|
| 四个 Tab、账号中心、更多选项、账号详情、热水详情、空设备页 | 保留 |
| 扫码、洗衣下单/支付、接水订单及完成页 | 隐藏 |
| 弹层 | 背景底栏保持原状态，但不可交互 |

Shell 向页面提供底部内容占位，逐步替换散落的固定底栏高度；安全区只计入一次。显隐随页面同一进度变化，避免动画结束后重排。键盘出现使用视图 inset，让输入框和提交按钮保持可达；不把键盘弹出误判为路由切换。

扫码继续走全屏路由，取消恢复入口，识别后只导航一次。外部支付宝的转场由平台掌控；应用只负责离开前处理中及返回后的核验/失败/取消状态，不把 App 恢复前台当作支付成功。

### 4. 弹层宿主统一进出生命周期

以复用弹层宿主管理遮罩、焦点和出入动画，设备与更多选项保留自己的内容组件。中心弹窗轻微缩放淡入；菜单从触发位置展开，边缘位置按可用空间约束。内部步骤共用遮罩，内容方向过渡并调整高度。替代条件分支立即删除组件，以保证退出动画完整。

关闭动作只处理最上层；动画结束后释放节点与焦点，并把焦点还给仍存在的触发入口。退出期间遮罩继续拦截，不能点击穿透。支持取消的弹层可通过遮罩/返回关闭；涉及既有不可取消操作时保持原有业务规则。平台权限弹窗使用系统行为，应用只控制权限引导层。

### 5. 条目及局部状态连续性

设备以设备 ID、订单以订单 ID、进行中任务以服务及会话/订单身份建立稳定 key，不用标题或整排拼接值充当身份。采用条目增删与尺寸过渡，让保留条目持续可见。分类和洗衣选项仅更新选中标记及关联内容；空态与内容、错误提示与无提示之间都保留出入生命周期。

按钮外部尺寸稳定，内部在标签、处理中和结果间交接；异步失败就近展示完整原因。RuntimeStatusBanner 不能在无消息时绕过动画宿主直接 return 空节点。热水操作只突出实际被操作的控件及最终状态，避免整块页面反复淡入。

登录成功仅在原页展开账号信息，焦点移出已消失表单并合理关闭键盘；默认系统变化继续遵守既有账号规则。添加和改名成功后关闭弹窗，使用稳定设备 ID 在列表短暂突出；失败保留输入和错误，不播成功反馈。

### 6. 接水结果展示与业务状态分离

以已确认终态生成带订单 ID 的不可变结果快照，在清理 currentWaterOrder 之前交给展示层。结果快照保存本次订单必要摘要，限定于当前流程；完成页不依赖“消息包含完成”或任意历史首条记录来识别成功。runtime 仍按既有终态写历史、清理活动订单和停止轮询。

移除 Shell 的自动回首页；当前订单完成后原地显示结果和“返回首页”。取消、失败分别显示真实状态；查询失败继续显示待确认或错误，不播放成功。重复轮询只交付一次同订单完成转换；旧订单异步响应不能覆盖新流程。进程重启不强制恢复完成页，记录仍通过已有历史查看。

### 7. 减少动效、开场与性能

响应系统 disableAnimations：关闭空间移动、压缩回弹和装饰动作，以即时状态变化或短淡变保留反馈；导航和结果不能依赖动画结束回调才能生效。普通模式避免开场覆盖层与首页重复入场，减少动效时取消固定开场等待。

一个操作只有一个主要视觉焦点；不让背景插图和无关卡片同时运动。使用稳定 child、局部监听及按需裁剪，只有实际测量证明必要时才加缓存/重绘边界，不引入大面积模糊。

## Risks / Trade-offs

- [导航栈改造改变返回和清理] → 先写账号多级返回、任务取消、扫码取消与支付恢复的行为测试，再替换宿主。
- [Tab 保活令计时器继续运行] → 显式可见性生命周期；检查切换前后轮询与 tick 数量，销毁时释放。
- [保留退出节点导致重复交互] → 旧节点禁用命中和语义，业务请求保持防重，遮罩持续到退出完成。
- [接水快照误判或串单] → 以当前订单 ID 与既有终态来源绑定，覆盖重复、失败、取消和晚到响应。
- [大字体、键盘导致尺寸过渡溢出] → 弹层可滚动、按钮稳定约束，测试窄屏和 200% 字体。
- [看起来不顺实际是掉帧] → 在 profile 模式真机记录帧时间，不以 debug 运行作为结论；以设备刷新率预算检查预热后脚本，目标至少 95% 帧的 UI/raster 各自不超预算，并记录异常原因。
- [所有交互同时变化难审查] → 同一 change 分模块落地与验收，每模块更新 tasks，问题记录到 bug.md；审查通过再继续，除非用户明确授权连续实施。

## Migration Plan

1. 建立交互清单及回归基线，确认当前用户修改；完成公共动效基础。
2. 改造路由、保活和底栏，随后统一弹层。
3. 完成列表/内容、登录/异步、接水结果及扫码支付往返。
4. 完成减少动效、布局、系统返回、真机性能及整体手感验收。
5. 无持久化迁移；回退时仅反向撤销本变更提交，保留用户既有修改和业务历史。各模块审查前不发布。
