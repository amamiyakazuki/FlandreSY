# 饮水单活动订单决策

- 用户明确选择 A：已有订单时先刷新旧订单；仅确认结束后才能创建新订单。查询失败、未结束或未知状态保留旧订单，不允许新订单静默覆盖。
- 实现进一步保证旧订单历史保存成功后才释放活动位置；新订单返回 ID 后先保存，再查询详情。详情失败不代表创建失败。
- 饮水终态只依据已确认状态码 50，不根据“完成/结束”等模糊文案猜测。
- 手动刷新、自动轮询及扫码前检查共享在途请求；页面瞬态清理不能取消操作互斥或丢掉订单。
- 与热水规则分离：热水随时开关，不意味着饮水允许随时创建新订单。饮水实体出水仍由机器按钮控制。
- 历史证据：Git `54274c1^:docs/ujing-water-flow.md`，创建接口提供 orderId，详情按 ID 查询；消费列表接口请求/响应契约仍未核实。
- 本轮新增 13 项测试，全量 72 项通过；不含真机/真实接口验证。下一模块 M3 账号隔离需单独推进，不把本次饮水修复视为全部业务完成。
